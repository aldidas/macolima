# Macolima Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI Mac app (sidebar / list / detail) to monitor and clean up containers, images and volumes on Colima, built from source via `make`.

**Architecture:** All logic lives in a Swift package `MacolimaKit` (unix-socket HTTP client, Docker Engine API wrapper, pure domain logic, Colima CLI wrapper, snapshot store) and is unit-tested with `swift test`. The app target `Sources/Macolima` is thin SwiftUI over one `@Observable AppModel`. XcodeGen generates the project; the Makefile mirrors `/Users/aldidas/Documents/Works/herdrm/Makefile`.

**Tech Stack:** Swift 6 toolchain (Swift 5 language mode is fine), SwiftUI, Darwin sockets, XcodeGen, xcodebuild, Swift Testing or XCTest (builder's choice, one only). No third-party Swift dependencies.

**Spec:** `docs/superpowers/specs/2026-10-19-macolima-design.md`

## Global Constraints

- Name `Macolima`; bundle id `dev.aldidas.macolima` (builder's call, spec left it open); no "Docker" in the name, no Docker or Colima logo; own icon.
- Minimum macOS 26 (`MACOSX_DEPLOYMENT_TARGET: "26.0"`); Liquid Glass via standard SwiftUI/AppKit materials.
- Native SwiftUI only; no third-party Swift dependencies.
- App Sandbox off; build-from-source only, ad-hoc signed (`CODE_SIGN_IDENTITY ?= -`); no notarization, updater or release binaries.
- `.xcodeproj` is generated by XcodeGen and gitignored.
- Docker access: Engine API over unix socket, API version negotiated via `/version` (not pinned); `/system/df` is fetched on view open and on Docker events, cached in memory, never polled on a timer.
- Socket from the active Docker context (`docker context inspect`), fallback `~/.colima/default/docker.sock`; single Colima profile, auto-detected.
- "Unused" = no container (running or stopped) references the image/volume.
- Deletes never pass `force`; deleting a container never removes its volumes; an image referenced by any container cannot be deleted.
- Host disk number = allocated bytes (`st_blocks * 512`) of the VM disk image found under `~/.colima/_lima/<profile>/`, shown beside the configured maximum.
- README and About screen state: "An unofficial, independent GUI for Colima. Not affiliated with or endorsed by the Colima project." MIT `LICENSE`.
- No menu bar item, compose up/down/pull, image building, networks view, localization.

## Review Focus

1. Container with several names or none: first name without the leading `/`; falls back to the short id.
2. Dangling image (no tags) used by a container referenced by image id: shown as `<none>`, counted as in use.
3. Volume whose `UsageData.Size` is `-1` (not computed): size shown as "unknown", sorted last, never counted as 0 bytes in prune totals.
4. Socket file exists but daemon is dead (connection refused) vs. file missing vs. Colima stopped: three distinct states.
5. Prune/multi-delete where one item fails mid-way (image became in use, volume vanished): other items still processed, failure reported per item.
6. TTY container logs (no multiplexed framing) and a partial frame split across reads.

public struct HTTPRequest { public init(method: String, path: String, query: [String: String] = [:], body: Data? = nil) }
